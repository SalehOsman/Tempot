## 1. Purpose & Core Doctrine

The **Impeccable Frontend Craftsmanship Discipline** eradicates generic, lifeless, and interchangeable user interface components commonly generated by automated AI assistants. Generic AI-slop interfaces are characterized by arbitrary paddings, uncalibrated color contrast, missing active and focus states, broken responsive wrapping, and complete disregard for bidirectional layout physics.

Impeccable establishes that software interfaces are precision instruments. Every pixel, margin, elevation layer, and transition duration must be mathematically intentional and grounded in a cohesive design token system:
- **Design Tokens as Source of Truth:** Hardcoded magic CSS numbers (e.g. `margin: 13px`) are strictly prohibited; layout must derive from calibrated design tokens.
- **Intentional Visual Hierarchy:** Content typography and container contrast must guide the human eye effortlessly toward primary actions.
- **Defensive Layout Engineering:** Interfaces must gracefully accommodate variable text lengths, dynamic localized content, and restricted mobile viewports without clipping or text overflow.

## 2. Visual Hierarchy & Spacing Invariants

Precision design requires deterministic spatial relationships and typographic calibration:

### The 8pt Baseline Grid System
- All margins, paddings, dimensions, and layout gaps must be multiples of 4px or 8px:
  - `4px` (micro spacing, icon-text gap)
  - `8px` (compact spacing, internal component padding)
  - `16px` (standard layout gap, form input spacing)
  - `24px` (section separation, card padding)
  - `32px` (major container padding)
  - `48px` / `64px` (page header and macro layout blocks)
- Arbitrary odd pixel values (`7px`, `11px`, `19px`) indicate ungrounded guesswork and trigger immediate quality rejection.

### Typographic Scale and Contrast
- Maintain a disciplined typographic hierarchy: Display, Title, Subtitle, Body, Caption, and Overline.
- Pair font sizes with proportional line heights to ensure optimal readability (`line-height: 1.5` for body text, `1.2` for display headings).
- Maintain distinct weight contrast between headings (`font-weight: 600` or `700`) and body copy (`font-weight: 400`).
- Ensure all text passes minimum WCAG 2.2 AA contrast ratios: at least `4.5:1` for normal text and `3:1` for large text against background layers.

### Purposeful Motion and Micro-Interactions
- Animations must serve functional orientation, never gratuitous visual decoration.
- Motion durations must remain snappy: `100ms` to `150ms` for hover and press micro-states, `200ms` to `250ms` for modal entry and drawer transitions.
- Always respect user system preferences: implement `@media (prefers-reduced-motion: reduce)` to disable non-essential motion.

## 3. Bidirectional Symmetry (RTL and LTR Parity)

Modern global applications require native, flawless support for both Left-to-Right (LTR) and Right-to-Left (RTL) writing systems (including Arabic and Hebrew):

1. **Strict Logical Property Enforcement:**
   Hardcoded physical directional properties in CSS and layout definitions are strictly forbidden:
   - Prohibited: `margin-left`, `margin-right`, `padding-left`, `padding-right`, `left`, `right`, `text-align: left`.
   - Enforced: `margin-inline-start`, `margin-inline-end`, `padding-inline-start`, `padding-inline-end`, `inset-inline-start`, `inset-inline-end`, `text-align: start`.
2. **Iconographic Directionality Invariant:**
   Direction-sensitive icons (such as directional arrows, navigation chevrons, step progress indicators, and back buttons) must automatically flip under RTL contexts. Static icons without directional meaning (e.g. search magnifying glass, lock, calendar, camera) must remain unflipped.
3. **Regional Baseline Localization:**
   Under User Global Rule #9, regional formatting, telemetry masking, and localized baselines are architectural standards and must never be stripped or degraded.

## 4. Mobile Golden Viewport Standard

Mobile interfaces demand ruthless economy of space and ergonomic touch engineering. Interfaces must conform to the **36/16/7/3 Layout Discipline**:

1. **36 Character Line Length:**
   Body copy in compact mobile viewports should maintain an optimal line measure of approximately 36 to 45 characters per line to eliminate reader eye fatigue.
2. **16px Primary Gutter:**
   Screen margins must preserve a consistent 16px lateral gutter across all mobile viewport widths, ensuring content never collides with device bezels or curved screen edges.
3. **7 Interactive Elements Maximum:**
   A single mobile view or navigation surface must contain no more than 7 primary interactive elements simultaneously, preventing cognitive overload and interaction clutter.
4. **3 Level Visual Depth Ceiling:**
   Elevations and background surface stack depth must never exceed 3 distinct layers (Base background, Card container, Interactive floating element/Modal). Excessive shadows and nested boxes degrade visual clarity.
5. **Ergonomic Touch Targets:**
   All touch targets (buttons, links, toggle switches) must measure at least `44x44px` with minimum `8px` separation between adjacent interactive targets.

## 5. Accessibility & Defensive UI Engineering

An interface is not complete until it is fully accessible to all users across all assistive technologies:

1. **WCAG 2.2 AA Compliance:**
   Zero inaccessible color combinations, zero missing text alternatives, and zero keyboard traps.
2. **Visible Focus Rings:**
   Never disable outline focus indicators (`outline: none` without a custom replacement is strictly banned). Every interactive component must provide a distinct, high-contrast `:focus-visible` ring.
3. **Semantic HTML First:**
   Always use semantic HTML elements (`<button>`, `<nav>`, `<main>`, `<dialog>`, `<section>`) before creating generic `<div>` wrappers with custom click handlers. Ensure proper ARIA roles, labels, and live regions where dynamic updates occur.
4. **Defensive Layout Resiliency:**
   Test components with 200% text zoom, 50-character internationalized label translations, and empty data states. Zero component should break, overlap, or clip text when labels expand.
